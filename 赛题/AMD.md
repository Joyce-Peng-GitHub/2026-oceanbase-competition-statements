# AMD

| 项目 | 说明 |
| --- | --- |
| 项目 | seekdb × AMD hipVS |
| 任务 | 使用 hipVS 加速 HNSW 索引构建 |
| 性能目标 | 在结果正确、检索质量达标的前提下，构建加速效果达到大赛公布的预期 |
| 提交产物 | 实现代码、可复现的测试方法及 CPU/GPU 构建性能对比报告 |
| 总分 | 20 |


## 一、题目背景
向量索引构建涉及大量距离计算和图结构处理。随着向量数量和维度增长，构建耗时会影响数据库的导入与检索准备效率。本题要求结合 AMD Radeon GPU 与 hipVS，优化 seekdb 的 HNSW 索引构建链路，并验证实际加速效果。

开始前，请阅读 [AMD Radeon 使用和部署 seekdb](https://yuque.antfin.com/ob/sr0nh6/rob7ng9zk9zznr2i)，完成算力平台、ROCm 和 seekdb 实验环境的准备。

## 二、题目内容
### 2.1 使用 hipVS 加速 HNSW 索引构建
1. 在 seekdb 中实现 hipVS 构建加速，使 AMD GPU 实际参与索引构建的核心计算。
2. 保持 seekdb 的 HNSW 索引使用语义，构建完成后能够通过 seekdb 正常执行向量查询，正确返回文档 ID 和检索结果。
3. 可优化批量构建、数据传输、图构建及必要的格式转换等环节；仅启用 GPU 查询、运行独立 GPU 演示或更改索引参数声明，不能证明完成了构建加速。
4. 保留 CPU 基线路径，确保普通 CPU 索引的行为不受影响。GPU 路径不可用时，应明确报错或记录回退，不能把 CPU 回退结果计作 GPU 加速成绩。

### 2.2 验证加速效果达到预期
在相同数据集与统一测试环境下，对比 CPU 基线和 hipVS 加速方案的索引构建耗时，计算：

```latex
构建加速比 = CPU 基线构建耗时 / hipVS 方案构建耗时
```

**“达到预期”指构建加速比达到大赛公布的目标，同时通过功能正确性与检索质量检查。** 具体目标倍数、数据规模及质量门槛由统一评测配置公布；本题当前不写死目标倍数。

## 三、验收标准
### 3.1 功能与质量
| 检查项 | 要求 |
| --- | --- |
| GPU 构建路径 | 有日志或性能分析证据证明 hipVS 实际参与构建，能识别是否发生 CPU 回退 |
| 索引可用性 | 完整处理测试向量，构建产物能够通过 seekdb 查询，无数据遗漏、ID 映射错误或非法结果 |
| 检索质量 | 使用相同查询集和精确近邻真值检查 Recall@K，CPU/GPU 均达到统一质量门槛 |
| CPU 路径 | 原有 CPU 索引仍可正常构建和查询 |
| 稳定性 | 重复构建与查询过程无崩溃、卡死或资源泄漏 |


不能通过减少数据量、降低精度、遗漏构建步骤或牺牲约定的检索质量来获得性能提升。

### 3.2 性能测试方法
1. **固定条件**：使用同一批向量、相同维度与距离类型，固定随机种子、CPU 资源、GPU 型号、软件版本和可比索引参数，记录全部配置。
2. **统一起点**：原始数据准备完成、待构建索引尚不存在时开始计时。CPU/GPU 两组均重新构建，不能复用已有索引或缓存的构图结果。
3. **统一终点**：索引完整构建并可供 seekdb 查询时结束计时。需包含数据扫描、CPU/GPU 传输、GPU 同步、格式转换及使索引可用所需的工作；延迟到首次查询的构建也须计入。索引可用性检查使用相同方法。
4. **区分开销**：数据生成、原始数据导入、环境启动单独记录。GPU 内核耗时可用于分析，但最终加速比按上述端到端构建耗时计算。
5. **重复测量**：每组至少执行 3 次，保留原始耗时，分别取 CPU/GPU 耗时中位数计算加速比；随后执行查询和 Recall@K 校验。

建议按以下格式记录实测结果，不填入参考实验中的查询耗时：

| 数据量 / 维度 | CPU 构建耗时 | hipVS 构建耗时 | 构建加速比 | CPU / GPU Recall@K | 是否达标 |
| --- | --- | --- | --- | --- | --- |
| 实测配置 | 实测中位数 | 实测中位数 | CPU / hipVS | 实测结果 | 对照统一评测目标 |


## 四、实验参考与提交材料
### 4.1 实验参考
参考 [seekdb × hipVS 实验 Notebook](https://github.com/zihaomu/notebook/blob/main/seekdb_hipvs_notebook/seekdb_hipvs_batch_demo_executed.ipynb)，可了解环境检查、CPU/GPU 对比和 Recall@10 的测量流程。

该记录在 10,000 条索引向量、4,000 条查询的场景下，展示了批量检索耗时从约 10,031.7 ms 降至 793.1 ms，约 **12.65 倍批量检索加速**。该数据比较的是 CPU 逐条检索与 GPU 批量检索，**不是索引构建加速比**；Notebook 也未提供完整的 CPU/GPU 构建耗时对比，不能据此判定本题达标。

Notebook 可用于了解实验环境和测量方法；本题需单独进行构建计时与达标验证。
